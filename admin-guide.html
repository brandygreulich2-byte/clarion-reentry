Website maintenance guide

Public website only. Never upload client names, inmate records, referral details, dates of birth, treatment records or private contact submissions. GitHub history retains previous versions, even after a file is edited.

Routine maintenance

  1. Check the live homepage, directory, calendar and PDF links every month.
  2. Review corrections against an official provider page and, where possible, confirm directly with the provider.
  3. Record the date, source URL, reviewer and whether provider confirmation occurred in a private working log that contains no client data.
  4. Edit assets/resources.json and the matching public resource profile in resources/. Check whether resource-directory.html contains a separate embedded listing that must also be updated.
  5. For an event, obtain public posting permission and update assets/events.json using the example format. Check the calendar displays it correctly.
  6. Upload changed files to your existing repository and commit with a descriptive message.
  7. Open the live site on a phone and computer after publishing; test search, navigation, downloads and emergency links.

Publishing with GitHub Pages

Open your repository. Use Add file → Upload files, keep the folder structure, and Commit changes. Do not upload the enclosing ZIP itself. GitHub Pages publishes from the configured branch; allow a few minutes and refresh.

To fix a mistake, edit the source file and commit a correction. Avoid putting sensitive information into GitHub even temporarily.

Quality and accessibility checks

  • All links work, including on a narrow mobile screen.
  • Every page has a clear heading, descriptive links and keyboard focus.
  • PDFs open and print; HTML alternatives remain available.
  • Resource status is accurate: published-source checked is not provider verified.
  • Events have real dates, public locations, source links and approval.
  • No contact form promises secure submission or collects private records.
